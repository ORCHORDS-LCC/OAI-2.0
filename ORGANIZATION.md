# ORCHORDS-LCC Organization

**ORCHORDS — BUILD DIFFERENT.**

ORCHORDS-LCC is a public GitHub engineering and research organization associated with **Orchords**, an independent software studio founded in 2025.

The public Orchords website describes the studio as independent and remote-first, with products at different stages of development. Public claims are intended to stay current, supportable, and clearly separated from plans or research.

Website: https://orchords.com/

## What we build

Current public product/work areas listed by Orchords include:

- **thewam.app** — active product work;
- **Orchords Security Scan** — live;
- **MissionControl** — in development;
- **OAI-2.0** — public next-generation coding-agent architecture and research workspace.

Product status can change. The website and each project's own repository/documentation should be treated as the current source of truth.

## How we work

Our public engineering work emphasizes:

- evidence before claims;
- source inspection before implementation;
- reproducible tests and verification;
- security-conscious defaults;
- explicit distinction between implemented, experimental and proposed work;
- public documentation that avoids credentials, private endpoints, sensitive datasets and private infrastructure details;
- direct, maintainable technical documentation with diagrams where they improve understanding.

## OAI-2.0

[OAI-2.0](https://github.com/ORCHORDS-LCC/OAI-2.0) is the organization's public research workspace for a next-generation coding agent focused on:

- code + vision reasoning;
- native dynamic tool calling;
- UI/UX and visual verification;
- adaptive reasoning;
- multi-agent orchestration;
- portable IDE/agent-host integration;
- evidence-driven completion.

The project is currently **PROPOSED / RESEARCH** unless a capability is explicitly marked otherwise.

## Contributions

Public contributions are welcome where a repository permits them.

Before contributing:

1. read the repository's `CONTRIBUTING.md`;
2. follow its license and public-safety boundaries;
3. do not publish secrets, customer information, private endpoints, sensitive training sources or non-public operational details;
4. distinguish proposals from implemented capabilities;
5. provide reproducible evidence for technical claims where possible.

For OAI-2.0, see:
https://github.com/ORCHORDS-LCC/OAI-2.0/blob/main/CONTRIBUTING.md
